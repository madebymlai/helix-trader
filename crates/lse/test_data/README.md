- `export_gcz6_book.parquet`, `export_gcz6_orders.parquet`: not captured. Helix's keys hold no Level 2 or 3 (CME Group Lite+ is Level 1 alone), so LSE's docs stand in: a book and an orders export of GCZ6 of 2026 by pair id 4000000002 over the second of `export_gcz6_trades.parquet`, built on 13 November 2026 with pyarrow as LSE's docs record the two files, zstd-compressed as LSE's files are. The columns are those of LSE's API docs ("The selection", read on 13 November 2026): the book `time, sequence, action, side, price, size, depth`, then ten bid and ten ask levels of price, size and orders, 67 columns, which LSE's Databank page names `bid_price_0`, `bid_size_0`, `bid_orders_0` to `ask_orders_9` when it reads a book's levels (its preview of the latest stored book, read on 13 November 2026); the orders `time, action, side, order_id, price, size`. The actions and sides are the codes LSE's CME stream documentation gives the same records ("The record"): A, M, C and N for a book's level or an order added, changed, removed or none, B and A for bid and ask. LSE's docs give no column types: the files type `time` as a `timestamp[ns, UTC]`, prices and sizes as doubles, the prices nullable, as LSE's captured CME exports do, `sequence` a `uint32`, a level's orders a `uint32` and `depth` a `uint8`, as Databento's MBP-10 records do, `action` and `side` strings, and `order_id` a string, as LSE's Python client and its pricing page's sample read them. The values are made up at GCZ6's tick of 0.10. The book holds four rows: an order joining the best bid; two of one time, the best bid's size changing then an order joining the best ask; and the ninth ask level removed, its last two ask levels empty (no price, no size, no orders). The orders hold five: two added at one time, one changed, one removed and one of no action (`N`, no price) at a third time.
