# Model strategies

Read the [strategy guide](../strategy/README.md) first for config, series, orders, bars and warmup. This guide covers the model-specific contracts; [`model_ema/`](../strategy/model_ema/) and [`config/model_ema.toml`](../../config/model_ema.toml) show their use. For walk-forward command orchestration see [backtest](../backtest/README.md); for live retraining operations see [live](../live/README.md); for futures calendar and transitions see [rolls](../rolls/README.md).

## Authoring and decisions

A model strategy's `Part` sets `TAKES_MODEL`, builds the shared `FeatureSet` through `ModelPart::features`, and delegates `Part::reads` to `model::reads`. Implement `ModelStrategy` with the same features in each mode; `ModelHandle` owns the decision path, not order submission. Register the strategy in `main.rs` for dataset, train, backtest and live as in the example.

Build features once in an ordered `FeatureSet`, with sources, feature-code version and warmup. Each indicator feature comes from a declared table: `.quotes(instrument_id, DECLARED, &config.indicators)`, and likewise `.trades`, `.bars`, `.depth` and `.deltas`, builds the table's indicator, names the feature and fingerprints its arguments; no call takes an indicator built by hand. The code decides which features exist and which series each reads; a table adds or removes none. A feature is named after its table when the table feeds it alone, and `<series>:<table>` when the table feeds several (a bar type, or `QuoteTick of <instrument>`). Custom-data features (`.data`) keep the name the code gives them. A feature is a Nautilus indicator exposing `Feature::value`; built-in moving averages already do, and a custom one brings its own argument type. The set registers bars, quotes and trades as indicators. Forward book depth, deltas and custom data to it from the corresponding handlers, including historical responses; warmup-built bars need forwarding too. The declared features and the target's ATR, if it has one, determine the series read and checked against config. Traded-instrument quotes added by the shared data requirements are not extra declared series.

A cadence is epoch-aligned and fires after the bar-build delay and a small margin, so a decision sees the bar closing on its grid in both replay and live. The delay is the bar types' in every node: five seconds after the close when any bar type is composite, so that its last source bar is in live, else none; a backtest and a dataset run build their bars and decide as late as live (`warmup::bar_build_delay`, `a_backtests_cadence_waits_for_composite_bars_as_a_live_ones_does`, `a_dataset_runs_cadence_waits_for_composite_bars`, `no_cadence_waits_for_bars_not_composite`, `a_decision_on_hour_bars_reads_the_bar_closing_on_its_grid`). Cadence decisions require fresh market data of the traded instrument since the preceding grid point; custom data and another instrument's activity do not establish freshness. Cold features or stale data produce no row or trade. Root tick features reset on a roll and must initialize on the new contract before deciding; see [rolls](../rolls/README.md).

The handle publishes a feature row and, in trading mode, returns a decision using the latest valid model for each enabled side. Live, it decides only once every warmup request has completed, as a warmup reaches the features window by window with the node running between them (`a_live_node_does_not_decide_until_its_warmup_ends`). A side model carries its payoff, the expected win and loss of its side's trade, and gives its expected net P&L at a calibrated probability and a unit (`store::SideModel::expected_pnl`): the payoff's expectation times the unit: with exits the decision's stop worth, the payoff being in R; without them one, the payoff being in money. Live trading, the meta's replay of the side models' decisions, the holdout's margin rule and the walk-forward's side scores all read that one value. A side must clear its configured margin; the higher expectation wins and a tie yields no trade (`payoff::pick`). No valid model, cold ATR, or a rounded exit at the reference price also yields no trade.

Send `decision.trade()` through `strategy::orders`: it has the target's instrument, size, exits and time limit. Dataset targets use the same trade path. Changing size, exits or holding time means the actual trade is not the target's trade: the model's holdout and expected P&L no longer describe it. Forward order events and time events to the handle, and time events first to the order module; rearm open trades on start. IB's execution client rejects the reduce-only orders needed here, so model strategies cannot trade live on IB; see [IB](../venues/ib/README.md#trading-and-warmup).

## Targets and datasets

A strategy has one target, `target` in `[model]`, whose exits are both present or both absent. `target = { take_profit = { atr = 2.0 }, stop = { atr = 1.0 }, limit = "45m", atr = { period = 14, ma_type = "WILDER" } }` is a bracket; `target = { limit = "45m" }` is a trade closed at its time alone, which has no exits and no ATR (`a_target_of_a_limit_alone_loads_with_no_exits`, `a_time_only_trade_has_no_exits_and_closes_at_its_limit`). One exit alone is refused under `model.target` with the section's other violations (`a_take_profit_or_a_stop_alone_is_refused_under_the_target`), as a Nautilus bracket has both.

A dataset run opens long and short target trades on Nautilus' simulated hedging venue at each decision (`D{n}-{L|S}-{E|TP|SL}`: `a_targets_orders_are_named_by_their_decision_side_and_leg`). Exits are distances in basis points or ATR multiples from the decision price, rounded to the instrument's tick grid; what is still open closes at the limit. ATR bars are derived from the traded instrument's declared inputs at the decision cadence; an `atr` table without a distance in ATRs is refused (`a_time_only_target_has_no_atr_to_warm_and_refuses_an_atr_table`). An uninitialized ATR or exit rounded to the reference price produces no target. Dataset outcomes are realized P&L net of simulated commission, with exits, commissions, exit distances and settlement times: a row has `long_pnl`, `long_commission` and `long_exit`, with exits `long_take_profit` and `long_stop`, then the same for `short_` (`a_bracket_has_a_column_per_value_of_each_side_its_distances_among_them`, `a_time_only_target_has_the_pnl_commission_and_exit_columns_of_each_side`), and settles when both sides have closed. Denied, rejected or unfilled entries and positions still open at stop leave decisions unsettled; inspect logs rather than assuming every decision became a row. Bars-only fills are optimistic, including high before low; see [backtest](../backtest/README.md).

Datasets are keyed by strategy and fingerprint and stored by day. A build replays from feature warmup before the first missing day through the target's limit after the last day, storing only decisions in the requested days. Ensure the catalog contains that prior history: replay does not check for it or request missing data. A recursive feature such as an EMA or Wilder ATR never completely forgets its starting state; use roughly 5–10 times the longest recursive period for negligible, not bit-identical, start dependence. Even a running sum can differ in its last bits across builds.

Rebuilding deletes the existing covered day files before writing because the catalog otherwise skips existing files; do not consolidate the dataset directory, since that loses day intervals. A train at `t` uses only decisions before `t` settled by `t`. Incomplete days are replayed to `t` and not cached as complete. Concurrent processes building the same strategy's dataset can race on day files and the manifest: do not backtest against the catalog and store a live node is retraining into at the same time.

## Training and acceptance

Each enabled side learns whether its target trade gains net of costs. The training window ends at `t`; its final holdout is preceded by an equally long calibration interval. Fit only on rows before calibration that settled by calibration start, calibrate on calibration rows settled by holdout start, and judge on holdout rows settled by `t`. This purging prevents target outcomes from leaking across boundaries; the target's limit also separates the window's decisions from first model use. The limit must be shorter than the decision cadence, so trades kept apart on the hedging dataset venue do not overlap in a live netting account, and than the window, both refused under `model.target.limit` (`a_limit_not_shorter_than_the_decision_cadence_is_refused_naming_both`, `a_limit_not_shorter_than_the_window_is_refused_under_the_limit`); a meta's window too short for it is the meta's to widen, refused under `model.meta.window` (`a_meta_window_not_longer_than_the_targets_limit_is_refused`). The window must leave fitting data before calibration and holdout.

Publish a side only if holdout calibrated log loss beats the training-mean baseline, its selected trades meet `min_trades` and `min_pnl`, and their net P&L per trade exceeds that of all side trades. AUC is reported, not an acceptance gate. Calibration is Platt's curve on a prediction's log-odds (`calibration::Calibration`): `a = -1, b = 0` leaves it as it is, and a slope near 0 says the model shows no signal (`a_model_already_calibrated_fits_the_curve_leaving_it_as_it_is`, `a_model_with_no_signal_fits_no_slope`). Holdout also reports the same selected trades under 1.5 times commission; this is a stress report, not another selection. A rejected or failed train keeps the current model, independently for each side. With exits the payoff uses each row's stop worth, and inverse instruments are refused, a stop on them having no worth in R (`a_target_with_exits_on_an_inverse_instrument_is_refused`); a time-only target's payoff is in money, and it works on them (`a_time_only_target_on_an_inverse_instrument_reads_its_trades_in_money`).

Meta-labeling lets a primary choose a side and a meta model decide whether to take its trade, on any target (`a_meta_model_on_a_time_only_target_is_loaded`, `a_meta_model_on_a_time_only_target_learns_from_its_trades`). The primary is the side models. A strategy decides on its cadence (`decision = { every = "1h" }`) and, at each tick (`decide::is_decision`), asks its model (`ModelHandle::decide`) only when its own signal, an indicator, fires. Meta rows use the primary model valid at each historical decision, out of sample, and exclude decisions where it would not trade. The meta model is calibrated and accepted on its own holdout, and a missing valid meta model means no trade. Optional sizing scales the target quantity by the meta probability; interpret the target trade's economics accordingly.

Which models a train at `t` fits is the schedule's plan, a function of the stores' valid-froms alone (`schedule::Schedule::plan`). Per model, the long, the short and the meta: one valid exactly from `t` is kept, not fitted again, and reported in use with its valid-from (`a_model_valid_from_the_train_is_kept_and_one_valid_before_it_is_not`, `a_model_already_published_at_the_trains_time_is_kept_in_use_and_the_other_fitted`); the others are fitted as of `t`. A model primary's meta waits for primary decisions while no primary model is valid before `t`, reported waiting with no fit attempted (`a_meta_waits_for_a_primary_model_before_the_train`, `a_meta_model_without_a_primary_model_before_it_waits`), and its rows never start before the primary's first model, which no decision precedes (`the_metas_rows_start_at_the_primarys_first_model_at_the_earliest`). A train replays once, from the first row its fits read, and not at all when it fits nothing, so rerunning `train --at t`, or a backtest's train at a partly published retrain time, fits only what is missing (`a_train_replays_no_day_before_the_primarys_first_model`, `a_train_with_every_model_in_use_replays_nothing_and_reports_each`). A train that kept no model succeeds and `train` exits 0; a model refused, failed or waiting fails it, with the reason (`a_train_keeping_no_model_succeeds_its_models_in_use_or_published`, `a_train_whose_meta_waits_fails_saying_so`). A backtest trains at a retrain time only where the plan fits a model, and builds its dataset from where the first plan's replay starts, the earliest row its fits read, a waiting meta and a kept model reading none, or from the first train time when that plan fits nothing (`a_backtest_from_an_empty_store_builds_from_the_primarys_window_its_meta_waiting`, `a_backtest_builds_no_day_before_the_primarys_first_model`). Its scores' periods are the schedule's retrain times, and each row decided with a model is scored beside that model's own baseline, the training mean of the labels of the rows it was fitted and calibrated on, which the train publishes in its manifest (`store::ModelManifest::baseline`, `a_published_sides_baseline_is_the_training_mean_of_the_rows_it_was_fitted_and_calibrated_on`, `a_published_metas_baseline_is_the_training_mean_of_the_rows_it_was_fitted_and_calibrated_on`): a model and its baseline are scored on the same rows, an earlier model in use where a train was refused beside its own baseline, each row of a period of models published off the schedule beside the baseline of the model that decided it, and a row with no model has no baseline score either (`each_period_scores_its_model_beside_that_models_own_baseline_on_the_same_rows`, `a_retrained_backtest_scores_an_earlier_model_in_use_beside_its_own_baseline`, `a_period_scores_each_row_beside_the_baseline_of_the_model_that_decided_it`, `rows_before_any_model_have_no_score_of_a_model_nor_of_a_baseline`).

`retrain` is optional in `[model]`. Left out, the strategy is never retrained (`schedule::Retrain`): each model, each side and the meta, is trained once, when a train finds none of it in use, and kept. A non-positive interval is reported under `model.retrain` with the section's other violations (`a_retrain_interval_not_positive_is_refused_with_the_sections_other_violations`). Never retrained, a model's current model at a train's time is the latest valid at or before it: the plan keeps it in use, reported in use since its valid-from, never retrained, and fits only the models with none (`never_retrained_the_latest_model_valid_by_the_train_is_kept_and_the_others_fitted`, `never_retrained_a_model_valid_before_the_train_is_kept_in_use_and_the_other_fitted`, `a_model_in_use_never_retrained_reads_as_in_use_since_its_valid_from`). A meta whose primary is in use is fitted alone, on the decisions of the very primary models it will filter (`never_retrained_a_meta_whose_primary_is_in_use_fits_alone`, `never_retrained_a_meta_whose_primary_is_in_use_is_fitted_alone`). With neither the meta nor a side of a model primary in use at a train's time `t`, one train trains both, at two times: the sides as of `t` less the meta's window (`MetaConfig::window`), fitted, calibrated and judged on rows of their own window back from there settled by then, and published valid from then; then the meta at `t`, on those sides' out-of-sample decisions over its window; all from one replay, so the meta filters the very primary it learned (`never_retrained_with_no_model_in_use_the_sides_fit_as_of_the_metas_window_before_the_train_and_the_meta_at_it`, `never_retrained_on_an_empty_store_a_train_fits_the_sides_as_of_the_metas_window_before_it_and_the_meta_at_it`, `a_two_time_trains_sides_are_judged_on_rows_settled_by_their_time`, `a_two_time_trains_meta_learns_from_the_sides_decisions_over_its_window`, `a_two_time_train_replays_once_from_the_sides_window_to_its_time`, `a_two_time_train_replays_from_the_sides_window_back_from_their_time`). A retrained strategy never trains so, a side fitted before a retrain time not being current at it (`retrained_every_model_fits_as_of_the_train`). With one side in use, the missing side and the meta are fitted at `t` (`never_retrained_with_one_side_in_use_the_other_and_the_meta_fit_at_the_train`). Should the sides fitted before `t` publish none, the meta waits for primary decisions, as the train reports (`a_two_time_trains_meta_fits_once_a_side_published_and_waits_if_none_did`, `a_primary_refused_in_a_two_time_train_leaves_the_meta_waiting`). A backtest trains at its start alone, where a model is missing; a second backtest of the span, or one from a later start, trains nothing (`a_backtest_never_retrained_builds_its_window_and_trains_at_its_start_alone`, `a_second_backtest_never_retrained_of_the_span_or_from_later_trains_nothing`). On an empty store, a model primary with a meta trains at two times there, and the backtest builds its dataset back to the sides' window before their time and trades from its start with both in use (`a_backtest_never_retrained_on_an_empty_store_builds_back_to_the_sides_window_and_has_both_in_use_at_its_start`). With no train after its start, it refuses to run when no side of the primary or no meta has a model in use there, naming which, both when the primary was refused and left the meta waiting (`a_backtest_never_retrained_with_no_primary_model_at_its_start_is_refused_naming_it`, `a_backtest_never_retrained_whose_meta_was_refused_at_its_start_is_refused_naming_it`, `a_backtest_never_retrained_whose_primary_was_refused_at_its_start_is_refused_naming_both`); a retrained backtest whose trains were all refused still runs (`a_retrained_backtest_whose_trains_were_all_refused_still_runs`). The scores cover the span as one period (`a_backtest_never_retrained_scores_the_span_as_one_period`), each model in use beside its own baseline, published with it where it was trained, however old the model (`a_backtest_never_retrained_scores_a_model_beside_its_own_baseline`), and a side with no model in use at the start has no baseline score either (`a_backtest_never_retrained_has_no_baseline_for_a_side_with_no_model_in_use`). With its models in use at its start, a backtest reads no row before it, and builds only the span's days (`a_backtest_never_retrained_with_its_models_in_use_builds_only_its_span`). Live, a strategy's retrains are a Nautilus actor of their own beside it, not its model handle's (`launcher::RetrainActor`); a strategy never retrained has no retrain actor, so no timer is set and no train launched (`a_strategy_never_retrained_has_no_retrain_actor_and_a_retrained_one_has_one`), and it trades on the store as it is, a model `train --at` publishes used from the next decision, which lists the store again (`a_model_published_while_live_is_used_from_the_next_decision`), deciding the bar-build delay late as any strategy does (`a_live_handle_never_retrained_waits_for_composite_bars`).

## Store, validity and versions

The dataset fingerprint includes ordered feature names, the series each feature reads (so a feature named after its table alone still keys its bar type or instrument), the parsed arguments of each feature table (serialized, so `"15m"` and `"900s"` match; tables built for the strategy's own logic are excluded), feature version and warmup, decision rule and its bar-build delay when non-zero (a strategy reading composite bars decides five seconds after its grid, so its datasets and stores are keyed apart from those built deciding on the grid; one reading none keeps the fingerprint it had: `a_strategy_on_composite_bars_is_keyed_by_its_build_delay`, `a_fingerprint_without_a_build_delay_keeps_the_rules_part_as_it_was`), the target and its ATR inputs (a time-only and a bracket target of one limit, and two limits, keyed apart: `a_time_only_and_a_bracket_target_of_one_limit_and_two_limits_are_keyed_apart`), dataset version, and normalized dataset venue costs, balance and leverage. Model store settings also key learner, retrain interval, window, holdout, acceptance minimums and side margin, and the store version, `store::VERSION`, under which every store of a strategy sits, its meta's too, so a model of another manifest is never read and the datasets keep their keys (`store::tests::bumping_the_store_version_keys_another_store`). A meta model's store is keyed by its primary's retrain interval, so a weekly-retrained strategy never trades on a model a daily-retrained one published between its retrains (`store::tests::a_store_lists_only_the_models_of_its_retrain_interval`). A strategy never retrained is keyed apart from every retrained one, so neither trades on the other's models (`store::tests::a_store_never_retrained_and_a_retrained_one_list_none_of_each_others_models`). Changing these selects different data or models rather than silently reusing incompatible results.

A strategy's models are one model set (`store::ModelSet`), built from the models root, the strategy id, the feature set, the model config, the data requirements and the dataset venue. It computes the dataset fingerprint once and keys every store from it, each side's the margins trade and the meta's, and only it builds a store. It hands out each side's and the meta's swap, already checked against that level's feature names and the fingerprint, and lists when each model was published, which the training's and the walk-forward's schedules read. The training, the walk-forward backtest and the handle each build theirs; the meta makes its rows from the model set as its stores are at that time.

A published model has a valid-from time and is written by rename. At each decision the handle selects the latest valid model and swaps only at that boundary. Before use it checks fingerprint, ordered feature names and width, then reproduces stored prediction probes bit for bit; a side model must also carry its payoff. A model failing a check is refused and the current one retained. A side with no valid model does not trade.

Bump the strategy's feature version when feature computation changes without a corresponding name, warmup or config change, such as a different input or formula. A changed feature-table argument is config and needs no bump. A rename or refactor preserving values needs no bump. Bump `store::VERSION` when what a published model's file holds changes, its manifest's fields or how a model is read from it: every model is trained again, on the datasets as they are. Bump `dataset::VERSION` when shared row-producing behavior changes for the same data and config: decisions, targets, fills, exits, P&L, commissions or shared features, including a Nautilus pin change affecting indicators, matching or fills. After the appropriate bump, update the golden rows and commit both version and snapshot:

```sh
GOLDEN_ROWS=write cargo test --test backtest backtest_golden_rows::
```
