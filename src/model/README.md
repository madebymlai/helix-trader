# Model strategies

Read the [strategy guide](../strategy/README.md) first for config, series, orders, bars and warmup. This guide covers the model-specific contracts; [`model_ema/`](../strategy/model_ema/) and [`config/model_ema.toml`](../../config/model_ema.toml) show their use. For walk-forward command orchestration see [backtest](../backtest/README.md); for live retraining operations see [live](../live/README.md); for futures calendar and transitions see [rolls](../rolls/README.md).

## Authoring and decisions

A model strategy's `Part` sets `TAKES_MODEL`, builds the shared `FeatureSet` through `ModelPart::features`, and delegates `Part::reads` to `model::reads`. Implement `ModelStrategy` with the same features in each mode; `ModelHandle` owns the decision path, not order submission. Register the strategy in `main.rs` for dataset, train, backtest and live as in the example.

Build features once in an ordered `FeatureSet`, with sources, feature-code version and warmup. Each indicator feature comes from a declared table: `.quotes(instrument_id, DECLARED, &config.indicators)`, and likewise `.trades`, `.bars`, `.depth` and `.deltas`, builds the table's indicator, names the feature and fingerprints its arguments; no call takes an indicator built by hand. The code decides which features exist and which series each reads; a table adds or removes none. A feature is named after its table when the table feeds it alone, and `<series>:<table>` when the table feeds several (a bar type, or `QuoteTick of <instrument>`). Custom-data features (`.data`) keep the name the code gives them. A quote feature formed over the target's bracket (`.over_bracket`, an `OverBracket` indicator) is handed the bracket's width as it is built (`TargetConfig::width`, the setter's `Distance::length` on the ATR the handle has the setter run on, `TargetSetter::sharing`), the decision each quote is read at and the target's limit; read in `Feature::value`, it is the width the decision's target is set at (`a_feature_over_the_bracket_reads_its_quotes_over_its_width`, `a_decisions_row_reads_the_width_its_trade_is_set_at`). A feature is a Nautilus indicator exposing `Feature::value`; built-in moving averages already do, and a custom one brings its own argument type. The set is registered with Nautilus for its bars alone. Its quotes and trades come through the strategy's warmup, a live warmup's responses and the live ticks alike: the warmup holds the live ones until its last window is answered, then hands them over in the order they came, dropping those the history holds by `ts_event` within their series, so a feature never reads time run backwards (`strategy::warmup`'s `hold`; `features_read_every_warmup_quote_before_a_live_one`, `live_quotes_at_or_before_the_historys_last_are_dropped_whatever_their_ts_init`). That hold stands in for Nautilus, which holds live ticks for its bar aggregators but not for an actor's indicators, until it does (helix-trader issue #16). A model strategy's data hooks are written once, by `model_data_hooks!` in its `DataActor` impl: they hand the warmup the responses, book depth, deltas and custom data among them, and the live quotes and trades. Warmup-built bars reach the features through the warmup too. No strategy hands the features live or replayed book depth, deltas or custom data, none declaring a feature on them: such a feature would read a live warmup's alone. The declared features and the target's ATR, if it has one, determine the series read and checked against config. Traded-instrument quotes added by the shared data requirements are not extra declared series.

A cadence is epoch-aligned and fires after the bar-build delay and a small margin, so a decision sees the bar closing on its grid in both replay and live. The delay is the bar types' in every node: five seconds after the close when any bar type is composite, so that its last source bar is in live, else none; a backtest and a dataset run build their bars and decide as late as live (`warmup::bar_build_delay`, `a_backtests_cadence_waits_for_composite_bars_as_a_live_ones_does`, `a_dataset_runs_cadence_waits_for_composite_bars`, `no_cadence_waits_for_bars_not_composite`, `a_decision_on_hour_bars_reads_the_bar_closing_on_its_grid`). Cadence decisions require fresh market data of the traded instrument since the preceding grid point; custom data and another instrument's activity do not establish freshness. Cold features or stale data produce no row or trade. Root tick features reset on a roll and must initialize on the new contract before deciding; see [rolls](../rolls/README.md).

The handle publishes a feature row and, in trading mode, returns a decision using the latest valid pair of the enabled sides, the sides one train published, valid from one time: a side's model with no other side's beside it is never used, so no decision mixes the sides of two trains (`a_side_published_without_the_other_is_never_used`, `a_two_sided_strategy_with_no_pair_takes_no_trade`). Live, it decides only once every warmup request has completed, as a warmup reaches the features window by window with the node running between them (`a_live_node_does_not_decide_until_its_warmup_ends`). It decides only once the target's ATR is initialized, which it reads itself rather than through Nautilus' registered indicators, and `decide::decide` publishes no row while a feature is cold, so a strategy holds no gate of its own (`no_row_is_published_while_the_targets_atr_is_cold`). A side model reads the side's row: the decision's features, then its own side's payoff features as the target sets them at the decision, which the dataset row of the decision holds alike (`deciding::SideRow`, `a_decision_reads_each_sides_row_as_its_dataset_row_holds_it`). It predicts its side's R, and the pair calibrates both sides' predictions together (`store::Pair::expect`, `calibration::Ksplit`): the level `C`, the mean of the two, by a line, `C' = alpha_C + beta_C C`, and the side call `D`, the long's less the short's, by a slope, `D' = beta_D D`, each side's expected R `E' = C' + D'/2` for the long and `C' - D'/2` for the short; a one-sided strategy's is its level line alone, on its one side's prediction, `D'` nought (`a_pair_in_hand_is_picked_among_on_its_calibrated_expectation`, `a_pair_expects_each_sides_r_through_its_calibration`). A side's expected net P&L is its `E'` times its unit: with exits the decision's stop worth, R being in stops; without them one, R being in money (`an_expected_r_is_weighed_by_the_unit_of_the_side`, `each_side_is_weighed_by_its_own_unit`). Live trading, the meta's replay of the side models' decisions, the train's picks on the holdout and the walk-forward's side scores all read that one value, and the decision carries it with its `C'` and `D'` (`handle::Decision`). A side must clear its configured margin; the higher expectation wins and a tie yields no trade (`payoff::pick`). A side expecting a loss does not clear a margin of nought however little its stop is worth (`a_side_expected_to_lose_on_a_half_tick_stop_does_not_clear_a_margin_of_nought`), and a side clearing its margin trades even with its stop in the market (`a_side_expected_to_gain_on_a_half_tick_stop_trades_its_stop_in_the_market`): on Nautilus' simulated venue the stop is rejected and the position runs without it to its take profit or its limit, a trade no row describes. No valid model, cold ATR, or a rounded exit at the reference price also yields no trade. The target is set before the models are asked, so an instrument missing from the cache is an error whatever the models, on every target (`no_model_valid_with_the_instrument_missing_from_the_cache_is_an_error`, `a_time_only_target_with_the_instrument_missing_from_the_cache_is_an_error`). The decision itself, the side picked, the meta's threshold and the size, is one module, `deciding::DecidingModels`, which sees no strategy, cache or clock: the handle and the meta's examples both decide through it.

Send `decision.trade()` through `strategy::orders`: it has the target's instrument, size, exits and time limit. Dataset targets use the same trade path. Changing size, exits or holding time means the actual trade is not the target's trade: the model's holdout and expected P&L no longer describe it. Forward order events and time events to the handle, and time events first to the order module; rearm open trades on start. On IB the exits and time close are not reduce-only, in a dataset run as live; see [IB](../venues/ib/README.md#trading-and-warmup).

## Targets and datasets

A strategy has one target, `target` in `[model]`, whose exits are one value, present or absent. `target = { bracket = { take_profit = { atr = 2.0 }, stop = { atr = 1.0 }, atr = { period = 14, ma_type = "WILDER" } }, limit = "45m" }` is a bracket; `target = { limit = "45m" }` is a trade closed at its time alone, which has no exits and no ATR (`a_target_of_a_limit_alone_loads_with_no_exits`, `a_time_only_trade_has_no_exits_and_closes_at_its_limit`). One exit alone, an exit beside the limit and an `atr` table on a time-only target cannot be written: parsing refuses each, on its own, before the section's other violations are looked for (`a_take_profit_or_a_stop_alone_is_refused_at_parsing_on_its_own`, `exits_beside_the_limit_are_refused_as_unknown`, `a_time_only_target_has_no_atr_to_warm_and_refuses_an_atr_table`). The prices stay one value to the order sent: `orders::Bracket`, held by `orders::Exits`, `targets::SideTarget` and `handle::Decision`, so a strategy reads every price from the decision.

A dataset run opens long and short target trades on Nautilus' simulated hedging venue at each decision (`D{n}-{L|S}-{E|TP|SL}`: `a_targets_orders_are_named_by_their_decision_side_and_leg`). Exits are distances in basis points or ATR multiples from the decision price, rounded to the instrument's tick grid; what is still open closes at the limit. ATR bars are derived from the traded instrument's declared inputs at the decision cadence. A bracket may mix the two (`a_bracket_mixing_atrs_and_basis_points_loads`); its `atr` table without a distance in ATRs is refused under `model.target.bracket.atr` (`an_atr_table_no_distance_uses_is_refused_under_the_bracket`). An uninitialized ATR or exit rounded to the reference price produces no target. One function sets a target for a dataset run and for a trading decision (`targets::TargetSetter::at`): it says why it set none, which a dataset run logs and a trading decision ignores (`a_target_on_a_cold_atr_says_so_and_names_its_bars`, `a_target_with_no_price_to_set_it_from_says_so`, `a_target_with_an_exit_on_the_price_says_so_and_names_the_price`). Every target reads its instrument, its payoff features costing its fills, so one missing from the cache is the setter's error, before any order (`a_time_only_target_missing_its_instrument_errs_before_any_order`). A payoff on an inverse instrument is no multiple of a distance in price, a stop's or a spread's, so a dataset run of any target on one fails as it starts rather than leaving an empty dataset (`a_target_on_an_inverse_instrument_fails_the_dataset_run`); so does one at a commission charged in another currency than the instrument's P&L currency, which is not converted (`a_commission_in_another_currency_than_the_targets_pnl_is_refused_as_the_targets_start`). Live, the setter errs at each such decision (`a_commission_in_another_currency_than_the_targets_pnl_is_an_error_at_a_decision`).

The commission of the run (`backtest::Commission`: a backtest's `--commission`, `--commission-rate` or `--commission-per-quantity`, handed to its dataset runs, or a live node's `--retrain-` ones, which key its store) is the one source of every cost. The fee model of a backtest's venues and of a dataset run's is made from it, and the target is handed it in every mode (`Mode::Dataset`'s `commission`, the venue's of `Mode::Backtest` and `Mode::Live`), with what a fill of a quantity at a price costs (`Commission::cost`), so a backtest's fills and a dataset's rows charge one trade alike (`a_backtest_and_a_dataset_run_charge_a_commission_per_quantity_alike`, `the_fee_model_charges_an_orders_first_fill_what_the_commission_costs`).

The target computes each side's payoff features as it sets it (`targets::PayoffFeature`), and they join every side model's row without the strategy listing them. Each is money over the side's unit: a long enters at the ask and a short at the bid of the instrument's last quote, and `c(p)` is what a fill at `p` costs. With a bracket, the take profit's R, `(up − ask − c(ask) − c(up)) / unit` for a long, and the stop's nominal loss before any overshoot, `(ask − down + c(ask) + c(down)) / unit`, a short mirroring them; on every target, the entry cost, `(ask − bid + c(entry)) / unit`, in money on a time-only target, whose unit is 1 (`a_brackets_payoff_at_a_commission_rate_is_worked_out_by_hand_on_each_side`, `a_brackets_payoff_at_a_commission_per_order_is_worked_out_by_hand_on_each_side`, `a_brackets_payoff_at_a_commission_per_quantity_is_worked_out_by_hand_on_each_side`, `a_time_only_targets_entry_cost_is_in_money_on_each_side`). On trades or bars alone, with no quote, both sides enter at the price the target is set from, with no spread (`a_bracket_on_trades_alone_reads_its_payoff_from_the_last_trade_with_no_spread`, `a_time_only_target_on_bars_alone_reads_its_payoff_from_the_last_close_with_no_spread`). A take profit realises its R: the hand-worked targets' take profits net exactly their take profit's R (`targets_on_quotes_are_the_outcomes_worked_out_by_hand`, `targets_on_minute_bars_are_the_outcomes_worked_out_by_hand`). Their names, `take_profit_r`, `stop_loss_r` and `entry_cost`, are written once and handed out by the target (`TargetConfig::payoff_names`, `a_target_names_the_payoff_features_of_the_barriers_it_has`); a side model's names are the strategy's, then those (`features::side_names`), which the dataset's manifest, a train, a store's manifests and a decision all read (`a_published_model_carries_its_schema_target_and_learner`). The meta model reads the strategy's features without them.

A row holds everything needed to read its trades, so training, scoring and the meta's examples read no instrument: beside its features and times, `long_payoff` (the long's payoff features, a list as wide as the target's payoff names), `long_pnl` (realized, net of simulated commission), `long_commission`, `long_exit` and `long_unit`, then the same for `short_`, the same columns on every target (`a_row_stores_each_sides_payoff_pnl_commission_exit_and_unit_under_its_names`); a row of another payoff width than the target's names is a schema mismatch (`a_row_of_another_payoff_width_is_a_schema_mismatch`). The unit is the stop's worth in money with exits and 1 on a time-only target (`a_bracket_is_set_on_each_side_with_the_worth_of_its_stop`, `a_time_only_target_is_set_with_a_unit_of_one`), and a trade's realised value is its P&L over its unit on every target. The stop's worth is exact, quantity times multiplier times distance in the target's P&L currency, not rounded to the currency's precision: half a cent for a stop half a tick from a mid on a half tick on one ounce of gold (`a_stop_half_a_tick_from_a_mid_on_a_half_tick_is_worth_exactly_that`, `a_stop_from_a_mid_on_a_half_tick_settles_at_its_exact_worth`), so a trade on a stop worth less than a cent realises a finite value (`a_trade_on_a_stop_worth_under_half_a_cent_realises_over_its_exact_worth`). The row answers whether a side gained, its trade, and each side's row and unit (`a_row_answers_each_sides_gain_trade_row_and_unit`). A row settles when both sides have closed. Denied, rejected or unfilled entries, a stop in the market, which the venue rejects (`a_stop_half_a_tick_from_a_mid_on_a_half_tick_is_rejected_and_stores_no_row`), and positions still open at stop leave decisions unsettled; inspect logs rather than assuming every decision became a row. Bars-only fills are optimistic, including high before low; see [backtest](../backtest/README.md).

Datasets are keyed by strategy and fingerprint and stored by day. A build replays from feature warmup before the first missing day through the target's limit after the last day, storing only decisions in the requested days. Ensure the catalog contains that prior history: replay does not check for it or request missing data. A recursive feature such as an EMA or Wilder ATR never completely forgets its starting state; use roughly 5–10 times the longest recursive period for negligible, not bit-identical, start dependence. Even a running sum can differ in its last bits across builds.

Rebuilding deletes the existing covered day files before writing because the catalog otherwise skips existing files; do not consolidate the dataset directory, since that loses day intervals. A train at `t` uses only decisions before `t` settled by `t`. Incomplete days are replayed to `t` and not cached as complete. Concurrent processes building the same strategy's dataset can race on day files and the manifest: do not backtest against the catalog and store a live node is retraining into at the same time.

## Training and acceptance

Each enabled side learns its target trade's realised net R, its net P&L over its unit, by a regression (`a_train_fits_calibrates_and_judges_each_side_on_its_part_of_the_window`). The training window ends at `t`; its final holdout is preceded by an equally long calibration interval. Fit only on rows before calibration that settled by calibration start, calibrate the pair together on calibration rows settled by holdout start, which the holdout is not among, and judge on holdout rows settled by `t`. This purging prevents target outcomes from leaking across boundaries; the target's limit also separates the window's decisions from first model use. The limit must be shorter than the decision cadence, so trades kept apart on the hedging dataset venue do not overlap in a live netting account, and than the window, both refused under `model.target.limit` (`a_limit_not_shorter_than_the_decision_cadence_is_refused_naming_both`, `a_limit_not_shorter_than_the_window_is_refused_under_the_limit`); a meta's window too short for it is the meta's to widen, refused under `model.meta.window` (`a_meta_window_not_longer_than_the_targets_limit_is_refused`). The window must leave fitting data before calibration and holdout.

A train's gate judges the decision the handle returns, on the target's trade; what a strategy then does with a decision stays outside its figures. A strategy's sides are trained and published as a pair or not at all: a pair is the sides one train publishes, valid from one time, and a one-sided strategy's is its one side (`a_long_only_model_trains_no_short`). A train fits every side of the pair without publishing; a side whose fit fails publishes neither, and the current pair stays (`a_side_whose_fit_fails_publishes_neither_side`). The pair's calibration (`calibration::Ksplit`) is fitted on both sides' predictions and R on the calibration rows: `beta_C` the least squares slope of the sides' mean R on `C`, `beta_D` that of the long's R less the short's on `D` through nought, each clipped to `[0, 1.5]`, a part whose predictions never vary having none, and `alpha_C` the mean R less `beta_C` times the mean `C`, after the clip (`a_slope_above_one_and_a_half_is_clipped_to_it_and_one_below_nought_to_nought`); a one-sided strategy fits the level line alone on its side's R (`a_one_sided_strategy_calibrates_its_level_line_alone_on_its_sides_r`). Each side's skill on the holdout, one less the squared error of its `E'` against its R over that of its own training-mean baseline, must be above nought, or the pair is refused (`a_skill_not_above_nought_is_refused`). The earnings are judged on the trades picked over the holdout rows (`deciding::DecidingModels::pick_among`) among the pair's own sides alone, never beside an older model of another side (`a_side_refused_on_its_skill_refuses_the_pair_judged_on_the_trains_own_picks`). A row where both sides clear their margins counts one trade (`a_row_where_both_sides_clear_counts_one_trade`). The picks must meet `min_trades` and `min_pnl`, and their net P&L per trade must exceed that of every trade of the pair's sides on the holdout rows. A one-sided strategy has no pick between sides and the same test as ever (`a_one_sided_strategy_taking_every_trade_of_the_holdout_is_refused`). `min_trades` counts the picks across the sides, so a two-sided strategy can meet it with half as many on each, and a strategy that picks almost nothing publishes nothing (`fewer_trades_picked_than_the_minimum_refuse_both_sides_and_publish_nothing`). Each side's mean `R - E'`, calibration slope (of `R` on `E'`, 1 of a calibrated model) and top-decile gap (the mean `R - E'` of the tenth of the rows expected the most) are reported, not acceptance gates (`the_sides_are_judged_on_the_trades_picked_on_the_holdout`). Holdout also reports the same picks under 1.5 times commission; this is a stress report, not another selection. The pair publishes together, as judged, with no refit, or is refused for the first reason found, a side's skill, the long's first, then the picks' minimums, and the current pair stays, so a profitable side paired with a losing one is refused with it (`the_sides_publish_together_on_what_their_picks_earned`, `a_profitable_side_paired_with_a_losing_one_is_refused_with_it`). Each side reports the pair's reason beside its own holdout, and each manifest holds the earnings of the pair's picks beside its side's own score, its mean `R - E'` among it, which the publish reports (`a_side_refused_on_its_skill_refuses_the_other_reporting_it_beside_its_own_holdout`, `with_both_sides_failing_their_skill_each_reports_its_own_and_the_pairs_earnings`, `both_manifests_hold_the_earnings_judged_beside_each_sides_own_score`). A two-time train judges as of the sides' earlier time, on the rows back from there (`a_two_time_trains_sides_are_judged_on_rows_settled_by_their_time`). A publish stays one rename per side, the long first: one failing keeps every side, failed (`a_publish_failing_publishes_no_other_side`, `a_publish_failing_after_the_others_leaves_no_pair_published`), and the sides published before it, as those a crash between the renames leaves, have no other side beside them at their valid-from, so are in no pair: no decision uses them, and the next train fits the pair again, its publishes replacing them (`a_side_published_at_the_trains_time_without_the_other_is_fitted_again_with_it`). Each side's manifest holds the pair's one calibration, naming the pair it was fitted on, its valid-from and its sides (`a_train_fits_calibrates_and_judges_each_side_on_its_part_of_the_window`).

A backtest's scores read the same picks (`walk::WalkForward::scores`), so they too judge the decision the handle returns, on the target's trade. A side's "Trades taken" count only the trades picked for it, at the commission and at 1.5 times it: on each row the decision picks among the sides of the pair in use then, on each side's row and unit (`deciding::DecidingModels::pick`), before any meta, so a row where both sides clear counts for the side expected the most, a tie for neither, and a side with no model beside it decides nothing (`each_trade_counts_for_the_side_picked_alone_where_both_sides_clear`, `a_sides_stressed_earnings_count_only_the_trades_picked_for_it`, `a_row_where_the_sides_tie_counts_no_trade_for_either`, `a_side_with_no_model_beside_it_decides_nothing`, `a_row_is_picked_on_each_sides_own_unit`, `a_sides_trades_picked_are_counted_before_any_meta`). Each side is scored on its model of that pair, a pair with a model failing its checks refused whole (`a_model_failing_its_checks_is_not_scored_and_the_current_one_is`). With no meta the sides' lines add up to the decisions returned; with one, its own section says which of the sides picked it took (`a_metas_earnings_read_the_trades_of_the_side_picked_from_its_threshold`). A side's "Every trade" stays its own, and its score, its `E'` against its R, its skill beside the baselines, its mean `R - E'`, its calibration slope and its top-decile gap, stays on all its rows with a model, so a model's expectations are still scored whole (`each_sides_every_trade_stays_its_own_beside_the_trades_picked`, `each_sides_score_stays_on_all_its_rows_with_a_model`); the meta's are its probabilities' AUC and log loss beside its baselines'. No section adds the sides up: the backtest's report gives what the strategy actually traded, which can differ from these lines whenever a strategy filters its decisions.

Meta-labeling lets the side models pick a side and a meta model decide whether to take its trade, on any target (`a_meta_model_on_a_time_only_target_is_loaded`, `a_meta_model_on_a_time_only_target_learns_from_its_trades`). A strategy decides on its cadence (`decision = { every = "1h" }`) and, at each tick (`decide::is_decision`), asks its model (`ModelHandle::decide`) only when its own signal, an indicator, fires. Meta rows use the sides' pair valid at each historical decision, out of sample, and exclude decisions where no side is picked; each reads the strategy's features, then the side picked and the decision's level `C'` and side call `D'` (`a_meta_model_decides_on_the_side_call_of_the_decision`). The meta model learns whether the trade of the side picked gains; it is calibrated by Platt's curve on its log-odds (`calibration::Platt`) and accepted alone, on its own holdout, its log loss below its training-mean baseline's, and a missing valid meta model or a NaN probability means no trade (`a_nan_meta_probability_takes_no_trade`). Optional sizing scales the target quantity by the meta probability; interpret the target trade's economics accordingly.

Which models a train at `t` fits is the schedule's plan, a function of the stores' valid-froms alone (`schedule::Schedule::plan`). Per model, the long, the short and the meta, the sides as their pair (`schedule::Models::pairs`): one valid exactly from `t` is kept, not fitted again, and reported in use with its valid-from (`a_model_valid_from_the_train_is_kept_and_one_valid_before_it_is_not`); the others are fitted as of `t`, the sides both, a side's model with no other beside it being no pair (`a_side_without_the_other_at_the_train_is_no_pair_and_both_sides_fit`, `a_side_published_at_the_trains_time_without_the_other_is_fitted_again_with_it`). A meta waits for the sides' decisions while no pair of the sides is valid before `t`, reported waiting with no fit attempted (`a_meta_waits_for_a_sides_model_before_the_train`, `a_meta_model_without_a_sides_model_before_it_waits`), and its rows never start before the sides' first pair, which no decision precedes (`the_metas_rows_start_at_the_sides_first_pair_at_the_earliest`). A train replays once, from the first row its fits read, and not at all when it fits nothing, so rerunning `train --at t`, or a backtest's train at a partly published retrain time, fits only what is missing (`a_train_replays_no_day_before_the_sides_first_model`, `a_train_with_every_model_in_use_replays_nothing_and_reports_each`). A train that kept no model succeeds and `train` exits 0; a model refused, failed or waiting fails it, with the reason (`a_train_keeping_no_model_succeeds_its_models_in_use_or_published`, `a_train_whose_meta_waits_fails_saying_so`). A backtest trains at a retrain time only where the plan fits a model, and builds its dataset from where the first plan's replay starts, the earliest row its fits read, a waiting meta and a kept model reading none, or from the first train time when that plan fits nothing (`a_backtest_from_an_empty_store_builds_from_the_sides_window_its_meta_waiting`, `a_backtest_builds_no_day_before_the_sides_first_model`). Its scores' periods are the schedule's retrain times, and each row decided with a model is scored beside that model's own baseline, the training mean of what it learned, a side's R and a meta's labels, on the rows it was fitted and calibrated on, which the train publishes in its manifest (`store::ModelManifest::baseline`, `a_published_sides_baseline_is_the_training_mean_of_the_rows_it_was_fitted_and_calibrated_on`, `a_published_metas_baseline_is_the_training_mean_of_the_rows_it_was_fitted_and_calibrated_on`): a model and its baseline are scored on the same rows, an earlier model in use where a train was refused beside its own baseline, each row of a period of models published off the schedule beside the baseline of the model that decided it, and a row with no model has no baseline score either (`each_period_scores_its_model_beside_that_models_own_baseline_on_the_same_rows`, `a_retrained_backtest_scores_an_earlier_model_in_use_beside_its_own_baseline`, `a_period_scores_each_row_beside_the_baseline_of_the_model_that_decided_it`, `rows_before_any_model_have_no_score_of_a_model_nor_of_a_baseline`).

`retrain` is optional in `[model]`. Left out, the strategy is never retrained (`schedule::Retrain`): each model, each side and the meta, is trained once, when a train finds none of it in use, and kept. ## Store, validity and versions

The dataset fingerprint includes ordered feature names, the series each feature reads (so a feature named after its table alone still keys its bar type or instrument), the parsed arguments of each feature table (serialized, so `"15m"` and `"900s"` match; tables built for the strategy's own logic are excluded), feature version and warmup, decision rule and its bar-build delay when non-zero (a strategy reading composite bars decides five seconds after its grid, so its datasets and stores are keyed apart from those built deciding on the grid; one reading none keeps the fingerprint it had: `a_strategy_on_composite_bars_is_keyed_by_its_build_delay`, `a_fingerprint_without_a_build_delay_keeps_the_rules_part_as_it_was`), the target and its ATR inputs (a time-only and a bracket target of one limit, and two limits, keyed apart: `a_time_only_and_a_bracket_target_of_one_limit_and_two_limits_are_keyed_apart`), dataset version, and normalized dataset venue costs, balance and leverage. Model store settings also key learner, retrain interval, window, holdout, acceptance minimums and both sides' margins, since one side's margin changes what the other publishes (`store::tests::either_sides_margin_keys_both_sides_stores`), and the store version, `store::VERSION`, under which every store of a strategy sits, its meta's too, so a model of another manifest is never read and the datasets keep their keys (`store::tests::bumping_the_store_version_keys_another_store`). A meta model's store is keyed by its sides' retrain interval, so a weekly-retrained strategy never trades on a model a daily-retrained one published between its retrains (`store::tests::a_store_lists_only_the_models_of_its_retrain_interval`). A strategy never retrained is keyed apart from every retrained one, so neither trades on the other's models (`store::tests::a_store_never_retrained_and_a_retrained_one_list_none_of_each_others_models`). Changing these selects different data or models rather than silently reusing incompatible results.

A strategy's models are one model set (`store::ModelSet`), built from the models root, the strategy id, the feature set, the model config, the data requirements and the dataset venue. It computes the dataset fingerprint once and keys every store from it, each side's the margins trade and the meta's, and only it builds a store. It hands out the swap of the sides' pairs (`store::Pair`) and of the meta's models, already checked against that level's feature names and the fingerprint, and lists when each model was published, which the training's and the walk-forward's schedules read; a pair's valid-from is a time every side traded has a model valid from (`schedule::Models::pairs`, `the_pairs_are_the_times_every_side_traded_has_a_model_valid_from`). The training, the walk-forward backtest and the handle each build theirs; the meta makes its rows from the model set as its stores are at that time.

A published model has a valid-from time and is written by rename. A store that cannot be read fails when the handle is built (`an_unreadable_store_fails_when_the_handle_is_built`). At each decision the handle lists the stores again and selects the latest valid pair of the sides and meta model, swapping only at that boundary; a failed listing is logged and keeps every previous list, so no decision mixes a fresh list with a stale one and a model already listed can still swap in (`a_failed_listing_keeps_the_previous_list`, `a_failed_listing_keeps_every_sides_previous_list`). Before use it checks fingerprint, ordered feature names and width, then reproduces stored prediction probes, the model's predictions before any calibration, bit for bit; a side model must also carry its pair's calibration, the same in each side's manifest and naming this pair, its valid-from and its sides, and a meta its own (`a_pair_whose_sides_hold_different_calibrations_is_refused_and_the_current_pair_kept`, `a_pair_whose_calibration_names_another_pair_is_refused_and_the_current_pair_kept`, `a_side_model_without_its_pairs_calibration_is_refused_and_the_current_kept`). A model failing a check is refused, a side's with its whole pair, and the current one retained (`a_pair_with_a_side_failing_its_checks_is_refused_and_the_current_pair_kept`). With no valid pair no side trades.

Bump the strategy's feature version when feature computation changes without a corresponding name, warmup or config change, such as a different input or formula. A changed feature-table argument is config and needs no bump. A rename or refactor preserving values needs no bump. Bump `store::VERSION` when what a published model's file holds changes, its manifest's fields or how a model is read from it: every model is trained again, on the datasets as they are, and a store of an earlier version is never listed, a model file of an earlier manifest refused when read, naming its file (`bumping_the_store_version_keys_another_store`, `a_model_of_the_earlier_manifest_is_refused_naming_its_file`). Bump `dataset::VERSION` when shared row-producing behavior changes for the same data and config: decisions, targets, fills, exits, P&L, commissions or shared features, including a Nautilus pin change affecting indicators, matching or fills; or when what a dataset's manifest holds changes, the rows staying as they are. After the appropriate bump, update the golden rows and commit both version and snapshot:

```sh
GOLDEN_ROWS=write cargo test --test backtest backtest_golden_rows::
```
