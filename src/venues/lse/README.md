# LSE history

`fill-catalog` fills the history of `LSEDGE` instruments, London Strategic Edge's own derived series, and of `GLBX` instruments, CME Globex contracts at Level 1, through the [node fill](../../catalog/README.md), each series' request naming the client of the [LSE adapter](../../../crates/lse/README.md). `LSEDGE`'s row of the [routing table](../mod.rs) takes definitions from the catalog alone, history and live data from LSE, and no broker: LSE trades nothing. `GLBX`'s takes definitions from [Databento](../databento/README.md), history from LSE, and live data and orders from [IB](../ib/README.md). Set `LSE_API_KEY` for `LSEDGE` and `LSE_CME_API_KEY`, a CME Group plan's key, for `GLBX` in the environment or `.env`; each is read only when something is missing. An `LSEDGE` series can be trades, LSE's tick slices; a `GLBX` contract's, trades or quotes, with the sizes LSE sends; quotes of an `LSEDGE` series fail with LSE's refusal, LSE serving a derived market's past as timeframes alone, and any other request fails as unsupported, a `GLBX` contract's book depths and deltas among them.

A `GLBX` contract takes the ID Databento gives it, in Nautilus' two-digit year: GCZ6 of 2026 is `GCZ26.GLBX`. LSE names it as CME does, by its year's last digit, a name that comes round every ten years, so the adapter asks LSE for the listing of the contract's month, which it looks up in LSE's catalogue (see [the adapter's instruments](../../../crates/lse/README.md#instruments)). Its definition is Databento's: the fill asks it of Databento's client, by client id, before the contract's series, over the span of what the catalog lacks of them, and the data engine writes it back to the catalog and puts it in the cache, where the LSE client reads its precision; once the catalog holds it, Nautilus answers from the catalog and Databento is not asked. Set `DATABENTO_API_KEY` too: it is read, and Databento's dataset end checked, whenever a `GLBX` series lacks something. CME Group Lite+ holds twelve years of Level 1 (`history-limit` before them). A day of a busy contract's quotes is past the rows one export may read (GCZ6's, about 2.7 million), so LSE is asked for it in halves.

An instrument is LSE's symbol, a hyphen and its LSE market in capitals: GOLD in `futures` is `GOLD-FUTURES.LSEDGE`, the 10-year Treasury futures `US10Y-FUTURES.LSEDGE` (see [the adapter's instruments](../../../crates/lse/README.md#instruments)). LSE publishes no definitions, so write each into the catalog by hand before filling, as an `IndexInstrument` of that id, LSE's symbol as raw symbol, the currency of its prices, a price precision and increment to its tick (gold to 0.1, the 10-year note to 1/64, 0.015625) and whole lots as sizes, stamped at 1970 so that it stands for any time; write it with Nautilus' catalog API (`ParquetDataCatalog::write_instruments`) on the pinned crates. No helix command writes one and the repository keeps none. The data engine answers each definition request from the catalog before asking LSE; a fill of an instrument the catalog does not define fails naming it before LSE is asked, and a definition coarser than LSE's prices fails the fill rather than round them.

Requests are split into day-long windows from the request start; the adapter asks LSE a UTC day an export within each, one download at a time on each key, within the calls a minute of the free plan, or of CME Group Lite on the CME key, unless configured otherwise, and asks again in halves for an export LSE refuses as too wide (past its 2,500,000 rows an export). LSE's refusal, such as `symbol-unknown` for a symbol it does not list or `plan-required`, fails the fill with its code, message and required plan; a quota (`rows-exhausted`, the free plan's 12.5 million rows a day, or `allowance-exhausted`, its 12.5 GiB a week) stops it with LSE's message, the windows filled before it kept, and the next run asks for what is still missing. LSE stores a UTC day the morning after it: a window reaching into the current UTC day, or into the day before while LSE answers no rows of it, is answered but not written back, the span logged, and the next run asks for it again. A window ending at the current day's midnight holds its first instant, so end a fill at the last instant of the day before (`…T23:59:59.999999999Z`) to have that day written back once LSE has loaded it. See the [adapter's exports](../../../crates/lse/README.md#exports) for retries, checksums and conversion, and [shared fill semantics](../../catalog/README.md) for coverage and resume.

A live run reading `LSEDGE` instruments is refused at startup: the adapter streams no live data yet. `GLBX`'s live data stays IB's until it does. A backtest simulates `LSEDGE` as a venue no broker trades: it starts with no money and keeps positions as Nautilus' venue default (see [backtest venues](../../backtest/README.md#leverage-and-venues)).

## Tests

Offline tests of the fill through the node against the adapter's mock LSE peer, and of a `GLBX` fill against it and a mock Databento peer, are in `src/venues/lse`, and a backtest reading a filled `LSEDGE` series beside IC's trade in `tests/backtest/backtest_read_only_venue.rs`; the adapter's own are in [the crate](../../../crates/lse/README.md#tests). The gated tests `tests/live/lse_history.rs` fill one day of gold and 10-year Treasury futures trades from LSE into a temporary catalog, and one day of GCZ26.GLBX's trades and quotes, its definition from Databento, with the keys of the environment or `.env` (`LSE_API_KEY`, `LSE_CME_API_KEY`, `DATABENTO_API_KEY`); they run only with `NAUTILUS_LSE_RUN=1` set in the shell and count against the free key's rows a day:

```sh
NAUTILUS_LSE_RUN=1 cargo test --test live lse_history:: -- --nocapture
```
