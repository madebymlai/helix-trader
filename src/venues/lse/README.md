# LSE history

`fill-catalog` fills the history of `LSEDGE` instruments, London Strategic Edge's own derived series, through the [node fill](../../catalog/README.md), each request naming the client of the [LSE adapter](../../../crates/lse/README.md). Their row of the [routing table](../mod.rs) takes definitions from the catalog alone, history and live data from LSE, and no broker: LSE trades nothing. Set `LSE_API_KEY` in the environment or `.env`; it is read only when something is missing. The declared series can be trades, LSE's tick slices, and bars, LSE's candles, from `1-SECOND-LAST-EXTERNAL` to `4-HOUR-LAST-EXTERNAL`, each stamped at its close, as every bar in helix is; a series LSE serves only as candles, such as gold spot (`XAU/USD-COMMODITIES.LSEDGE`), is filled as bars. A bar type of another width, of another price, or daily and longer is refused naming it (see [the adapter's exports](../../../crates/lse/README.md#exports)); any other request fails as unsupported.

An instrument is LSE's symbol, a hyphen and its LSE market in capitals: GOLD in `futures` is `GOLD-FUTURES.LSEDGE`, the 10-year Treasury futures `US10Y-FUTURES.LSEDGE` (see [the adapter's instruments](../../../crates/lse/README.md#instruments)). LSE publishes no definitions, so write each into the catalog by hand before filling, as an `IndexInstrument` of that id, LSE's symbol as raw symbol, the currency of its prices, a price precision and increment to its tick (gold futures to 0.1, the 10-year note to 1/64, 0.015625, gold spot to 0.01) and whole lots as sizes, stamped at 1970 so that it stands for any time; write it with Nautilus' catalog API (`ParquetDataCatalog::write_instruments`) on the pinned crates. No helix command writes one and the repository keeps none. The data engine answers each definition request from the catalog before asking LSE; a fill of an instrument the catalog does not define fails naming it before LSE is asked, and a definition coarser than LSE's prices fails the fill rather than round them.

Requests are split into day-long windows from the request start, as Databento's; the adapter asks LSE a UTC day an export within each, one download at a time, within the calls a minute of the free plan unless configured otherwise, and asks again in halves for an export LSE refuses as too wide (past its 2,500,000 rows an export). LSE's refusal, such as `symbol-unknown` for a symbol it does not list or `plan-required`, fails the fill with its code, message and required plan; a quota (`rows-exhausted`, the free plan's 12.5 million rows a day, or `allowance-exhausted`, its 12.5 GiB a week) stops it with LSE's message, the windows filled before it kept, and the next run asks for what is still missing. LSE stores a UTC day the morning after it: a window reaching into the current UTC day, or into the day before while LSE answers no rows of it, is answered but not written back, the span logged, and the next run asks for it again. A window ending at the current day's midnight holds its first instant, so end a fill at the last instant of the day before (`…T23:59:59.999999999Z`) to have that day written back once LSE has loaded it. See the [adapter's exports](../../../crates/lse/README.md#exports) for retries, checksums and conversion, and [shared fill semantics](../../catalog/README.md) for coverage and resume.

LSE's reference series, the rows of its reference collections, are custom data of no instrument, `LseRow` (see [the adapter's reference rows](../../../crates/lse/README.md#reference-rows)): a strategy's config lists each in `[data].custom` by its type and metadata, `{ data = "Custom:LseRow", metadata = { source = "bond_yields", symbol = "US10Y" } }` for the US 10-year yield of the daily bond yields, and data requirements carry it as its Nautilus data type (`DataRequirements::custom`), keyed in the catalog by its identifier, `US10Y-BOND_YIELDS`. They need no definition and no venue: `fill-catalog` asks LSE's client for each over the fill's window, whole, and Nautilus writes the rows back as custom data under that identifier; custom data of any other type of no instrument fails the fill before anything connects. Each row is stamped when its values are known, a date's at its end, an interval's at its close, so a window holds the rows known in it. LSE stores a date the morning after it, as it does a market's day: a window whose last date LSE may not have loaded yet is answered but not written back, the span logged, and the next run asks for it again. A backtest replays the rows by that data type, registering LSE's type itself. A live run reading any is refused before anything connects: the adapter streams none yet.

A live run reading `LSEDGE` instruments is refused at startup: the adapter streams no live data yet. A backtest simulates `LSEDGE` as a venue no broker trades: it starts with no money and keeps positions as Nautilus' venue default (see [backtest venues](../../backtest/README.md#leverage-and-venues)).

## Tests

Offline tests of the fill through the node against the adapter's mock LSE peer are in `src/venues/lse`, a backtest reading a filled `LSEDGE` series beside IC's trade in `tests/backtest/backtest_read_only_venue.rs`, and one replaying filled bond yields to the strategy in `tests/backtest/backtest_custom_series.rs`; the adapter's own are in [the crate](../../../crates/lse/README.md#tests). The gated tests `tests/live/lse_history.rs` fill one day of gold and 10-year Treasury futures trades, one day of gold spot candles as 1-minute bars, and one day of the daily 10-year US bond yield, from LSE into a temporary catalog, with the key of the environment or `.env`; they run only with `NAUTILUS_LSE_RUN=1` set in the shell and count against the key's rows a day:

```sh
NAUTILUS_LSE_RUN=1 cargo test --test live lse_history:: -- --nocapture
```
